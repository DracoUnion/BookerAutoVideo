# 漫剧 Agent 概要设计文档

**文档版本**：v1.0
**编写日期**：2026-10-10
**文档状态**：草案

---

## 1. 引言

### 1.1 编写目的

本文档定义漫剧 Agent（Comic Drama Agent，以下简称 CDA）的概要设计，明确系统的总体架构、模块划分、模块职责、关键数据流、外部接口及非功能性约束，作为后续详细设计与编码实现的依据。

### 1.2 项目背景

用户提供一段文字剧本（或故事梗概），系统自动完成从剧本到成片的制作流程：拆解分镜、生成/接收图片素材、生成关键帧、合成视频。目标是让创作者以最小的操作成本产出漫剧短片，同时保留对中间产物的干预能力。

### 1.3 术语定义

| 术语 | 说明 |
|------|------|
| 分镜（Shot） | 一个连续镜头，是最小的视频生成单元 |
| 场景（Scene） | 同一地点、同一时间下的一组分镜 |
| 关键帧（Keyframe） | 单个镜头动画的起始帧与结束帧 |
| 素材（Asset） | 可用于生成关键帧或视频的图片资源 |
| 剧本（Script） | 用户输入的原始文字内容 |
| 分镜方案（Storyboard） | 剧本拆解后的结构化产物 |

### 1.4 设计范围

本文档覆盖 CDA 的核心流水线、数据模型与 CLI 交互设计。**不包含**：Web UI、用户账户体系、素材版权校验、多用户并发调度。

---

## 2. 系统概述

### 2.1 系统定位

CDA 是一个**本地运行的命令行工具**，以单用户、单项目为操作粒度。它不承担服务端职责，所有产物落盘到本地目录，用户对中间产物有完全的可见性与可替换性。

### 2.2 核心能力

1. **剧本拆解**：调用 LLM 将自由文本剧本转换为结构化分镜方案。
2. **素材获取**：对每个分镜生成图片，或接收用户提供的图片并做定向编辑。
3. **关键帧生成**：为每个分镜生成起始帧与结束帧，锚定动画的起止状态。
4. **视频合成**：基于关键帧生成分镜视频，并拼接为成片。

### 2.3 设计原则

| 原则 | 说明 |
|------|------|
| 阶段可独立执行 | 四个阶段各自可单独运行，中间产物落盘，支持断点续跑 |
| 产物可干预 | 用户可替换任一中间产物（如图片），后续阶段自动采纳 |
| 数据契约先行 | 所有跨模块数据由 Pydantic 模型约束，禁止裸 dict 传递 |
| 模型能力可替换 | LLM、图像模型、视频模型均可通过配置切换后端 |
| 最小依赖 | 仅依赖 `pydantic`、`openai`、`ffmpeg`（外部命令）|

## 3. 总体架构

### 3.1 分层视图

```
┌─────────────────────────────────────────────────┐
│                   CLI 层                         │
│   break / images / keyframes / video 四个子命令   │
└──────────────────────┬──────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────┐
│                 Pipeline 层                      │
│  ScriptBreaker → ImageGen → Keyframe → VideoGen  │
└──────────────────────┬──────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────┐
│                 Adapter 层                       │
│   LLMAdapter / ImageAdapter / VideoAdapter       │
└──────────────────────┬──────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────┐
│              外部服务 / 工具层                    │
│   OpenAI API · 视频模型 API · ffmpeg            │
└─────────────────────────────────────────────────┘
```

### 3.2 模块清单

| 模块 | 职责 | 输入 | 输出 |
|------|------|------|------|
| CLI | 参数解析、阶段调度、错误提示 | 命令行参数 | 退出码、日志 |
| ScriptBreaker | 剧本 → 分镜方案 | 剧本文本、风格预设 | `Storyboard` |
| ImageGen | 分镜 → 图片素材 | `Storyboard`、用户素材 | `[ImageAsset]` |
| KeyframeGen | 分镜 + 图片 → 关键帧对 | `Storyboard`、`[ImageAsset]` | `[KeyframePair]` |
| VideoGen | 关键帧 → 分镜视频 → 成片 | `[KeyframePair]` | `[VideoResult]`、成片 mp4 |
| ProjectStore | 中间产物读写、路径管理 | 项目 ID | 落盘文件 |

### 3.3 数据流

```
剧本.txt
   │
   ▼
[ScriptBreaker] ──► storyboard.json
                        │
                        ▼
                  [ImageGen] ◄── 用户素材（可选）
                        │
                        ▼
                   images/*.png
                        │
                        ▼
                 [KeyframeGen]
                        │
                        ▼
                keyframes/*_start.png
                keyframes/*_end.png
                        │
                        ▼
                  [VideoGen] ──► shots/*.mp4
                        │
                        ▼
                   final.mp4
```

每一阶段的产物都落盘，形成一条**可回溯的产物链**。任一环节的产物被用户手动替换后，后续阶段读到的即为替换后的内容。

## 4. 模块设计

### 4.1 CLI 模块

采用子命令模式，每个子命令对应一个流水线阶段。

| 子命令 | 功能 | 关键参数 |
|--------|------|----------|
| `break` | 剧本拆解 | `--script`、`--style`、`--output` |
| `images` | 图片生成/接收 | `--storyboard`、`--user-images`、`--output` |
| `keyframes` | 关键帧生成 | `--storyboard`、`--images`、`--output` |
| `video` | 视频生成与合成 | `--keyframes`、`--backend`、`--output` |

**设计约束**：
- 每个子命令只依赖上一阶段的落盘产物，不依赖进程内状态。
- 参数校验失败时返回非零退出码并给出明确提示。
- 支持 `--dry-run`，打印将执行的步骤而不实际调用外部 API。

### 4.2 ScriptBreaker 模块

**职责**：将自由文本剧本转换为符合 `Storyboard` schema 的结构化数据。

**处理逻辑**：
1. 读取剧本与风格预设。
2. 构造 system prompt，注入拆解规则（角色锚点、景别变化、prompt 英文要求）。
3. 调用 LLM 的结构化输出接口，直接获得 `Storyboard` 实例。
4. 若返回 refusal，抛出可读错误；否则落盘 `storyboard.json`。

**关键设计**：角色外观锚点（`CharacterAppearance`）在此阶段一次性固化，后续所有图像 prompt 都必须嵌入对应角色的外观描述，这是保证跨镜头一致性的核心机制。

### 4.3 ImageGen 模块

**职责**：为每个分镜产出图片素材，支持三种来源。

| 来源 | 触发条件 | 处理方式 |
|------|----------|----------|
| generated | 默认 | 按 `image_prompt` 文生图 |
| user_provided | 用户指定了该 shot 的图片 | 直接登记，不调用生成 |
| edited | 用户指定图片且要求调整 | 以用户图片为底图做图像编辑 |

**处理逻辑**：
1. 遍历 `Storyboard` 中的全部 shot。
2. 检查用户素材映射（`shot_id → path`）：
   - 命中且无需调整 → 登记为 `user_provided`；
   - 命中且需调整 → 调用图像编辑接口 → `edited`；
   - 未命中 → 文生图 → `generated`。
3. 输出 `[ImageAsset]`，文件按 `shot_{id:03d}.png` 命名。

### 4.4 KeyframeGen 模块

**职责**：为每个分镜生成起始帧与结束帧。

**处理逻辑**：
1. 对每个 shot，调用 LLM 生成两个 prompt：`start_frame_prompt` 与 `end_frame_prompt`。
2. 两段 prompt 共享角色外观、场景、光线，仅构图/姿态/机位不同。
3. 以两段 prompt 各生成一张图，构成 `KeyframePair`。
4. 若该 shot 的图片素材来自用户，可将用户图片作为起始帧，仅生成结束帧（减少不一致）。

**可选性**：若视频后端支持“参考图生视频”，关键帧可作为可选优化；若走“图生视频”路线，则关键帧为必要输入。模块本身不强制依赖，由 CLI 参数控制。

### 4.5 VideoGen 模块

**职责**：将关键帧转为分镜视频，并拼接为成片。

**处理逻辑**：
1. 对每个 `KeyframePair`，选择视频后端生成分镜视频。
2. 异步任务需轮询直至 `succeeded` / `failed`。
3. 全部完成后，用 ffmpeg 按 shot 顺序拼接为 `final.mp4`。

**后端抽象**：定义 `VideoBackend` 协议，至少实现两个后端：

| 后端 | 模式 | 特点 |
|------|------|------|
| Sora | 提交 + 轮询 | 支持参考图，质量高 |
| Runway | 异步任务 | 批量场景下可控性好 |

CLI 通过 `--backend` 切换，避免绑定单一供应商。

### 4.6 ProjectStore 模块

**职责**：统一管理项目目录与产物路径。

**目录结构**：
```
outputs/{project_id}/
├── storyboard.json
├── images/
├── keyframes/
├── shots/
└── final.mp4
```

**设计约束**：所有读写路径由 ProjectStore 统一构造，禁止模块内硬编码路径拼接。

## 5. 数据模型设计

### 5.1 模型清单

| 模型 | 用途 | 关键字段 |
|------|------|----------|
| `CharacterAppearance` | 角色外观锚点 | name, appearance, clothing, color_palette |
| `Shot` | 单个分镜 | shot_id, shot_type, camera_move, image_prompt, dialogue |
| `Scene` | 场景 | scene_id, location, time_of_day, mood, shots |
| `Storyboard` | 分镜方案（顶层） | project_id, title, style_preset, characters, scenes |
| `ImageAsset` | 图片素材 | shot_id, image_path, source |
| `KeyframePair` | 关键帧对 | shot_id, start_frame, end_frame, motion_description |
| `VideoResult` | 分镜视频 | shot_id, video_path, duration_seconds, model_used |

### 5.2 设计要点

- **枚举约束**：景别（`ShotType`）与运镜（`CameraMove`）使用枚举，避免 LLM 输出自由文本导致下游处理困难。
- **字段描述即指令**：所有 `Field(description=...)` 会作为 JSON Schema 的一部分传给 LLM，是控制生成质量的主要手段。
- **路径类型**：文件路径统一使用 `Path` 类型，便于校验与跨平台。
- **可序列化**：所有模型支持 `model_dump_json` / `model_validate_json`，作为落盘与读取的标准方式。

## 6. 接口设计

### 6.1 外部接口

| 接口 | 用途 | 调用方式 |
|------|------|----------|
| Chat Completions（Structured Output） | 剧本拆解、关键帧 prompt 生成 | 同步 |
| Images Generate | 文生图 | 同步 |
| Images Edit | 图生图（素材调整） | 同步 |
| Videos Create / Retrieve / Download | 视频生成 | 异步轮询 |
| ffmpeg（命令行） | 视频拼接 | 子进程 |

### 6.2 内部接口

模块间通过 Pydantic 模型与文件路径交互，**不通过全局状态**。每个阶段的入口函数签名为：

```
阶段函数(上一阶段产物, 配置) -> 本阶段产物
```

这一约束保证了阶段的可测试性与可独立执行性。

## 7. 关键流程

### 7.1 全流程（Happy Path）

```
1. 用户执行 break    → 得到 storyboard.json
2. 用户执行 images   → 得到 images/*.png
3. 用户执行 keyframes → 得到 keyframes/*_start.png, *_end.png
4. 用户执行 video    → 得到 shots/*.mp4 与 final.mp4
```

### 7.2 素材干预流程

```
1. 用户在 images 阶段通过 --user-images 传入 {shot_id: path}
2. ImageGen 命中映射 → 跳过生成 / 执行编辑
3. 后续阶段自动读取替换后的图片
```

### 7.3 单镜头重跑流程

```
1. 用户删除 keyframes/ 下某个镜头文件
2. 重新执行 keyframes 阶段
3. KeyframeGen 检测缺失并补齐
4. 重新执行 video 阶段，仅重生成缺失的分镜视频
```

## 8. 非功能性设计

| 维度 | 要求 |
|------|------|
| 可维护性 | 模块间低耦合，单一职责；外部服务通过适配层隔离 |
| 可测试性 | 每个阶段可独立调用，外部 API 可 mock |
| 可扩展性 | 新增视频后端只需实现 `VideoBackend` 协议 |
| 容错性 | 单镜头失败不阻断整体流程，记录失败清单供重跑 |
| 性能 | 图像/视频生成支持并发（可配置并发度），ffmpeg 拼接串行 |
| 成本可控 | 提供 `--dry-run`，打印预估调用次数与 token 消耗 |
| 可观测性 | 关键步骤输出结构化日志（阶段、shot_id、耗时、状态）|
| 安全性 | API Key 从环境变量读取，不写入配置文件或产物 |

## 9. 技术选型

| 项 | 选型 | 理由 |
|----|------|------|
| 语言 | Python 3.10+ | 与 OpenAI SDK、Pydantic 生态契合 |
| 数据建模 | Pydantic v2 | 结构化输出、校验、序列化一体 |
| LLM/图像/视频 | OpenAI SDK | 统一 SDK 覆盖结构化输出、图像、视频 |
| 视频拼接 | ffmpeg | 事实标准，无需额外依赖 |
| CLI | argparse | 标准库，零依赖 |
| 配置 | 环境变量 + CLI 参数 | 简单直接，符合单用户工具定位 |

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 角色跨镜头外观漂移 | 成片不连贯 | 强制外观锚点注入 prompt；提供角色参考图机制 |
| LLM 输出不符合 schema | 拆解失败 | 使用 Structured Outputs 保证 schema 合规 |
| 视频模型额度/延迟 | 流程阻塞 | 后端可切换；支持单镜头重跑；失败清单 |
| 关键帧起止差异过大 | 视频抖动 | 结束帧 prompt 约束共享环境与角色；限制运镜幅度 |
| 用户素材风格与生成素材不一致 | 观感割裂 | 提供图像编辑路径，允许用户素材走风格统一处理 |
| API 成本失控 | 费用超预期 | dry-run 预估；并发度可配置；缓存已生成素材 |
