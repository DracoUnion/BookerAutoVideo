# 任务书：为 BookerAutoVideo 新增 `copy` 子命令（视频逆向还原提示词 → Seedance 复刻生成）

## 1. 背景与目标

`BookerAutoVideo` 已具备抽帧、图像哈希、多模态 LLM 编排、ffmpeg 封装、YAML 缓存等能力。现需新增一个子命令 **`copy`**，实现“爆款短视频复刻”工作流：

> **输入一段参考视频 → 抽帧 → 感知哈希提取关键帧 → 视觉大模型逆向还原 Seedance 提示词 → 调用 Seedance API 生成复刻视频 → 下载到本地**

要求：**严格遵循现有工程约定**（argparse 子命令注册方式、LLM 公共参数、`openai.py` 客户端层、`util.py` 缓存、`doc/` 文档），**不得破坏任何现有子命令**。

## 3. 功能需求（五阶段流水线）

| 阶段 | 名称 | 输入 | 输出 | 缓存 |
|---|---|---|---|---|
| S1 | 抽帧 | 视频文件 | 按 `sample_fps` 采样的帧序列（内存） | 可选落盘 `frames/` |
| S2 | 关键帧提取 | 帧序列 | 关键帧列表（含时间戳、图片路径） | `keyframes/` + `keyframes.json` |
| S3 | 逆向提示词 | 关键帧 + 视频时长 | `reversed_prompt.txt` | 命中则跳过 LLM 调用 |
| S4 | Seedance 生成 | 提示词 + 时长/分辨率/画幅 | 任务 ID → 视频 URL | `seedance_task.json` |
| S5 | 下载 | 视频 URL | `<out>/copy_<ts>.mp4` | 已存在则跳过 |

**断点续跑**：任一阶段产物已存在且校验通过，则跳过该阶段；`--force` 强制重跑。

**干跑模式**：`--dry-run` 只执行 S1–S3，输出逆向提示词后停止，不调用 Seedance。

## 4. CLI 设计

### 4.1 子命令签名

```
BookerAutoVideo copy <VIDEO> [options]
```

### 4.2 参数表

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `VIDEO` | 位置参数 | 必填 | 参考视频路径 |
| `-o/--out` | str | `output/copy` | 输出目录 |
| `--sample-fps` | float | `1.0` | 初筛抽帧频率 |
| `--phash-threshold` | int | `10` | pHash 汉明距离阈值 |
| `--max-keyframes` | int | `10` | 送视觉模型的关键帧上限 |
| `--hash-size` | int | `8` | pHash 尺寸 |
| `--vision-detail` | choice | `low` | `low`/`high`，OpenAI 图片 detail |
| `--gen-duration` | int | `8` | Seedance 生成时长（4/8/12） |
| `--gen-resolution` | str | `1080p` | 生成分辨率 |
| `--gen-ratio` | str | `16:9` | 画幅 |
| `--gen-audio` / `--no-gen-audio` | flag | 开 | 是否生成音频 |
| `--seedance-key` | str | 环境变量 | Seedance API Key |
| `--seedance-host` | str | 环境变量 | Seedance Base URL |
| `--seedance-model` | str | `seedance-2.0` | 生成模型名 |
| `--poll-timeout` | int | `600` | 轮询超时秒 |
| `--dry-run` | flag | 关 | 只到 S3 |
| `--force` | flag | 关 | 忽略缓存重跑 |
| `--keep-frames` | flag | 关 | 保留全部采样帧 |

### 4.3 公共参数使用约定

- `-vm/--vmodel`：**视觉模型**（S3 必用）。若未传，回退到 `-m/--model`；二者皆空则报错退出。
- `-m/--model`：文本模型，用于 S3 提示词的**最终润色/结构化**（可选步骤，`--no-polish` 可关）。
- `-k/--key`、`-H/--host`：OpenAI 鉴权与网关，S3 直接复用。
- 重试/温度/超时：沿用入口公共参数。

### 4.4 新增环境变量（`.env` / 系统环境）

```ini
SEEDANCE_API_KEY=
SEEDANCE_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
SEEDANCE_MODEL=seedance-2.0
```

CLI 参数优先级：**CLI > 环境变量 > 默认值**。

## 6. 数据模型（`copy_models.py`）

```python
class VideoMeta(BaseModel):
    path: str
    fps: float
    total_frames: int
    duration: float
    width: int
    height: int

class Keyframe(BaseModel):
    index: int
    time: float          # 秒
    path: str            # 关键帧图片路径
    phash: str           # 十六进制哈希

class CopyState(BaseModel):
    video_hash: str      # 视频文件内容 sha256 前 16 位，作缓存键
    stage: str           # done_s1 ... done_s5
    meta: VideoMeta
    keyframes: list[Keyframe] = []
    reversed_prompt: str | None = None
    polished_prompt: str | None = None
    seedance_task_id: str | None = None
    video_url: str | None = None
    output_path: str | None = None
```

缓存路径：`data/copy/<video_hash>/state.yaml`（复用 `util.py` 的 Pydantic YAML 缓存）。

## 7. 关键实现要点

### 7.1 S1 抽帧
- 优先用 `ffmpeg.py` 封装抽帧到临时目录（按 `sample_fps`）；若封装不便，允许 `cv2.VideoCapture` 逐帧读、按 `step = round(fps/sample_fps)` 采样。
- 必须读取并记录 `VideoMeta`（fps、总帧、时长、宽高）。

### 7.2 S2 pHash 关键帧
- 每帧转 RGB → `imagehash.phash(pil, hash_size)` → 与上一关键帧汉明距离比较，`> threshold` 记为关键帧。
- 首帧必为关键帧；若候选数超 `max_keyframes`，**均匀采样**截断。
- 关键帧写盘：`data/copy/<hash>/keyframes/kf_<i>_t<time:.2f>s.jpg`。
- 边界：无关键帧（如纯色视频）→ 报错退出码 2，提示调低 `--phash-threshold`。

### 7.3 S3 逆向提示词
- 图片压缩：最长边 ≤ 768，JPEG quality 85，base64 内联 `data:image/jpeg;base64,...`。
- 按时间顺序把关键帧写入 user message，附时间点文本。
- **system prompt 固定**（`copy_pmt.py`）：

```
你是一名 AI 视频提示词逆向工程师。用户按时间顺序提供同一段视频的若干关键帧。
请逆向还原一段可直接用于 Seedance / 即梦文生视频模型的提示词，要求：
1. 描述主体、场景、动作、镜头运动、光线与色调、氛围；
2. 还原镜头节奏（推拉摇移、快慢切换）；
3. 给出建议时长（4/8/12 秒）与画幅（16:9 / 9:16）；
4. 只输出最终提示词，中文为主，必要时保留英文风格关键词，不要任何解释。
```

- 调用 `-vm` 模型；若返回 400 且信息含 `image_url` 不支持，明确报错“视觉模型不支持图片输入”。
- 可选润色：把原始提示词 + 生成参数交给 `-m` 模型，输出**一段 final prompt + 一个 JSON 参数块**（duration/ratio/style），用 `--no-polish` 关闭。

### 7.4 S4 Seedance 生成
- 新建 `seedance.py`，封装：
  - `create_task(prompt, duration, resolution, ratio, model, audio) -> task_id`
  - `wait_task(task_id, timeout, poll_interval) -> video_url`
  - `download(url, dest)`
- 鉴权：`Authorization: Bearer $SEEDANCE_API_KEY`，Base URL 来自 `--seedance-host` / `SEEDANCE_BASE_URL`。
- 优先使用官方 `seedance-sdk`；若引入 SDK 增加过重依赖，**允许直接 HTTP 调用**（`requests`），但必须封装在 `seedance.py` 内部，不散落在主模块。
- 轮询间隔 3s，超时抛异常，`state.yaml` 记录 `task_id`，续跑时**先查已有 task 状态**而非重复创建。

### 7.5 S5 下载
- 目标路径：`<out>/copy_<video_hash>_<ts>.mp4`；已存在且大小 > 0 则跳过。
- 流式下载，失败重试 3 次（指数退避）。

## 8. 错误处理与退出码

| 场景 | 行为 | 退出码 |
|---|---|---|
| 视频不存在/无法打开 | 明确报错 | 2 |
| 未配置视觉模型（`-vm` 与 `-m` 均空） | 报错并提示参数 | 2 |
| 无关键帧 | 报错 + 调参建议 | 2 |
| 视觉模型不支持图片 | 报错 + 换模型建议 | 3 |
| Seedance 鉴权失败（401/403） | 报错 + 检查 key/host | 4 |
| 轮询超时 | 报错 + 保留 task_id 供续跑 | 5 |
| 下载失败（重试后） | 报错 + 保留 URL | 6 |
| 任一阶段异常 | 写 `state.yaml` 记录已成功阶段 | 对应码 |

## 12. 约束与注意事项

1. **不改动现有模块的公开行为**：`openai.py`、`util.py`、`ffmpeg.py` 只允许**新增**函数，不允许改签名。
2. **不在 `__main__.py` 里写业务**，只加 `copy_video.reg_subparser(subparsers)` 一行。
3. **提示词与参数解耦**：`copy_pmt.py` 只放模板字符串，便于后续换模型调优。
4. **密钥安全**：日志中不得打印 API Key；`state.yaml` 不落密钥。
5. **大文件处理**：抽帧不得一次性把整段视频读入内存；关键帧 base64 发送前必须缩放。
6. **可测试性**：S2（pHash 选择）与 S3 的图片编码应拆成纯函数，便于单测；建议在 `examples/` 放一段 5–10s 样片或在测试中生成合成视频（`cv2.VideoWriter` 生成渐变色视频即可覆盖 S1/S2）。
